## Contexto
O repositório é a vitrine do portfólio: ele precisa estar organizado desde o primeiro dia.

## O que fazer
- [ ] Criar o repositório **público** no GitHub (sem segredos, nunca!)
- [ ] Clonar na máquina e abrir no VS Code
- [ ] Subir a documentação inicial (`README.md`, `CLAUDE.md`, `docs/`, `.github/`)
- [ ] Rodar `scripts/criar-sprint.sh 1` (cria labels, milestone e as issues desta sprint) *(se ainda não foi feito)*
- [ ] Criar um **GitHub Project** (Board) com as colunas: Backlog, A fazer, Em andamento, Em teste, Feito
- [ ] Adicionar as issues da Sprint 1 ao board
- [ ] Preencher descrição e tópicos do repositório (`nextjs`, `threejs`, `react-three-fiber`, `supabase`, `real-estate`)

## Critérios de aceite
- [ ] Repositório público com README renderizando os diagramas
- [ ] Labels e milestone "Sprint 1 – Ambiente" criados
- [ ] Board com as issues da sprint

## Como testar
Abrir o repositório no navegador e conferir README, issues, labels e board.
